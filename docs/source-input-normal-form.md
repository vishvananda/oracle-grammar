# A proved source input in an activation

An activation's explicit `Query(CostObjects(Activation, [component], Inputs,
Before), 0)` identifies its source when that exact top-level cost component is
an unrestricted `Sacrifice(One(Source))`, or one unrestricted `Move` selection
of `One(Source)` into Exile. Comparison uses Source for that one proved input.
The address is checked against the actual cost, rather than a first sacrifice.

Cost input histories record identities. Before identifies the original
incarnation, and a copied activation retains the original payment's inputs.
The source role identifies that same original incarnation. Characteristic
information and explicit historical/captured wrappers retain their own timing.
This proof does not turn a recorded movement outcome into a live zone query.

Performed histories can be empty or redirected by replacement processing;
After names a resulting incarnation. Neither is reduced. Resolution payments,
nonzero indexes, nested component addresses, arbitrary choices, mixed selections,
other objects and more than 64 cost parts also remain distinct. Unknown query
fields cannot disappear. No typed identifier leaves are removed: Activation,
the source, the component address and the singleton index contain no binding IDs.

The bounded typed walker applies the proof within its owning activation.
Created delayed Programs retain the captured payment; descendant Ability
frames establish their own payment and source roles. Mapped canonicalization
must preserve every target and result origin. The authored print form retains
the input query; printing an edited cost must still verify against that cost's
current operands. Supported distinct meanings remain separate readings.

On the immutable 32,755-face allowed retirement checkpoint, this proof merges
118 encodings across 113 faces: 110 change from two readings to one, two from
four to one, and Torch Song from four to two. Every old supported meaning is
preserved, with no added meanings; all 33,562 resulting readings validate in
full-card context. The 113 affected faces keep exact keyed wording and verified
semantic roundtrips. Torch Song's two remaining readings each retain exact and
default printing. These are representation and pipeline checks, not game-state
simulation. Characteristic timing remains explicit in the original operands.

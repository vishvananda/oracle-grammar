# Immediate scalar parameters and one-object choices

A pure scalar capture immediately preceding its only consumer can share that
consumer's parameter evaluation point. Comparison inlines it for one Draw,
GainLife, LoseLife, Mill, Scry or Surveil recipient, or a common LoseLife or Mill
amount for the ability controller's opponents. The proof also covers
DealDamage's common amount, one object counter placement, one Snapshot pump's
stats, and the two stats of one defined token. The capture has one
definition, and every typed use must be one of the audited next parameters.
Intervening effects, later uses and captures in future programs prevent the
reduction. Enclosing abilities with independent descendant Ability scopes keep
the existing conservative capture policy.

The parameters are evaluated before the consuming operation changes game state.
The token subset creates exactly one token for one player from the creating
effect's definition, with no chosen attributes, abilities, copied abilities or
additional entry state. Its stat expressions use the creating scope and are
evaluated before creation. Several tokens or players, rules-defined recipes,
copy recipes and entry choices retain their captures. Live continuous effects
remain separate from Snapshot pumps.

The shared bounded pure-read proof admits deterministic arithmetic and current
object/player queries, announced X, the matched event amount and party size.
It also admits recorded payment inputs, object transitions, a matched event
group or block pair, recorded die results, simple event counts and totals, and
snapshots tied to the turn boundary or the casting of this spell. These reads
observe the same state before the atomic operation or Snapshot effect.
Captured characteristic views and primitives retain their original form.
Signed substitution checks overflow and preserves
dynamic count validation rather than introducing a negative literal count.
Cloned target/binding leaves retain their original sites; removed capture sites
are accounted for by mapped canonicalization. Ordinary authored print operands
retain the immediate capture.

A second proof concerns a directly preceding ChooseObjects operation whose
native singular-operation contract establishes a maximum of one chosen object.
The next Move, Reveal, Destroy, DiscardObjects or SetTapped selector can express
`One(Result(choice, After, 0))` as `Selected(choice)`. Empty choices select nothing
in both forms. The result ID and its origin move intact, with no zone query or
incarnation change. Before, nonzero indices, plural/dynamic choices, nonadjacent
definitions and gathered loop results provide no such proof. A local choice and
consumer within one loop iteration retain that local result context; exported
gathered sets cannot acquire a scalar result reference.

Both proofs require strict lossless native instruction shapes; captures also
require the complete typed result-use context. They introduce no first-match
semantic choice. Every printed edited value must still reparse from its current
operands, independently
of exact wording or agreement with the reference.

Printing also tries at most three inverse views: immediate scalar captures,
one-object choice receipts, and their combination. The same operation and
cardinality proofs govern both directions. Synthesized captures use fresh IDs
outside every original typed result ID, including nested scopes and unresolved
references; at most 64 captures are introduced per view. A view must normalize
to the input before it is offered to the printer. The original forms remain
available, and every candidate text still requires a verified reparse.
